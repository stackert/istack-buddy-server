## Forms Core BE — Emails

- Doc ID: 32000
- Area: backend/core/forms
- Scope: outbound emails generated by the Core Forms backend

### Email types
- Confirmation emails (to submitter)
- Notification emails (to form owners/recipients)
- System emails (failures, reports complete, other operational notices)
  - SendGrid webhook notifications (bounces, spam, blocks) processed internally
  - User email saves/exports (when enabled)
  - Admin/ops notices related to limits, security, or jobs

### Triggers and context
- Submission-created triggers (confirmation/notification)
- Submit-action outcomes that enqueue emails (e.g., payment success/failure)
  - Payment-related emails are tied to payment actions and status messaging; most integrations do not directly send emails from submit-action code, but may influence confirmation/notification content.
- Scheduled/batch/reporting events

### Composition and content sources
- Templates and substitutions
  - Emails use templates populated with form field values and system variables. Changes to field labels/options can affect substitutions; validate templates after major form edits.
- Attachments
  - Attachments (e.g., PDF exports, signatures) are added at composition time and must meet provider size limits. HIPAA accounts may replace attachments with secure links to private storage. Signatures can be embedded or linked per policy.

### Delivery
- Transport (SMTP/API)
- From/reply-to rules and domain restrictions
- Rate limiting, retries, bounces (high level)
  - From/reply-to: sender may be normalized to allowed domains; reply-to defaults to configured address when not provided.
  - Provider: most production email uses SendGrid subaccounts; SMTP credentials selected per account/subaccount; fallback/test services (e.g., Mailpit in dev) may be used.
  - Retries/bounces: failures are logged at send time; SendGrid webhooks record bounce/spam events; excessive failures may trigger suppression. Misconfigured TLS on HIPAA may log errors.

Queries for delivery outcomes
```
_sourceCategory=formstack/prod/*
 "Successfully sent email message"
| json auto
| where formId = "_FORM_ID_" and externalServiceName = "SendGrid"
```
```
_sourceCategory=formstack/prod/*
 "SendGrid webhook for sendgridMessageId"
| json auto
| where sendgridEvent in ("bounce","spamreport","dropped")
```

### HIPAA and compliance
- Content redaction and attachment restrictions for HIPAA accounts
- Secure links vs embedded content
  - HIPAA: enforce TLS, avoid embedding PHI in URLs or attachments where restricted; prefer secure links to files stored in private buckets; non-compliant transports are blocked or logged as errors.
  - Known issues: if encryption keys or secure link generation fails, attachments may be omitted or replaced with notices; ensure account settings permit the intended mode.

### Observability
- Log messages to trace enqueue/send results
- Sumo queries to find sent/failed emails by formId/submissionId/recipient
  - Local logs include attempts and outcomes (success/failure), with formId, recipient, service name, HIPAA flags, and SendGrid subaccount when applicable.
  - SendGrid webhooks are logged with event type (bounce, spam, delivered) and message identifiers.
  - Working Sumo examples:

| json auto
| where formId = "_FORM_ID_"

### Correlation examples
- By recipient (across prepared, sent, and webhook in one view)
```
_sourceCategory=formstack/prod/*
 ("Email prepared for delivery for" or "Successfully sent email message" or "SendGrid webhook for sendgridMessageId")
| json field=_raw "context.formId" as formId
| json field=_raw "context.recipient" as recipient
| json field=_raw "context.sendgridEvent" as sendgridEvent
| where formId = _FORM_ID_ and recipient contains "_RECIPIENT_PART_"
```

- By SendGrid message id (all webhook events for that message)
```
_sourceCategory=formstack/prod/*
 "SendGrid webhook for sendgridMessageId"
| json field=_raw "context.sendgridMessageId" as sendgridMessageId
| json field=_raw "context.recipient" as recipient
| json field=_raw "context.sendgridEvent" as sendgridEvent
| where sendgridMessageId = "_SENDGRID_MESSAGE_ID_"
```


### Troubleshooting Steps
- Verify trigger occurred (submission, submit action, scheduled job)
- Check logs for enqueue/send, bounces, and policy blocks
- Validate recipient, domain, and SMTP configuration
  - Confirm the submission created event and that email configuration is enabled for the form/account.
  - Inspect send attempts and outcomes; if SendGrid is used, check webhook events for suppression/bounce.
  - Validate sender domain rules and TLS requirements (especially for HIPAA accounts); ensure attachments are within limits.

Notes on SendGrid vs other transports
- Most production emails use SendGrid (subaccounts per account type); logs include `externalServiceName: SendGrid` and `sendGridSubAccount` when applicable.
- To verify delivery path: search for "Successfully sent email message" and check `externalServiceName`. For webhook-side status, use the SendGrid webhook query above.

### Testing strategies
- Test modes and sandboxing
- Expected headers and rendering checks
  - In dev environments, Mailpit may be used; verify headers (from/reply-to) and TLS where required. Rendering checks include template substitution success and presence/absence of attachments per policy.
